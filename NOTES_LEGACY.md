# Legacy-клиент (ITDOLegacy) — статус и ограничения

Этот файл фиксирует реальные технические границы задачи "клиент под iOS
7-12, 32-bit", чтобы не создавать иллюзию, что это решено одной сборкой.

## Что сделано

- Отдельный таргет `ITDOLegacy` в `project.yml`, полностью независимый от
  основного `ITDOApp` (SwiftUI, iOS 17).
- UIKit + программный Auto Layout, без SwiftUI, без Scene lifecycle
  (`UIApplicationSceneManifest`), без `async`/`await`, без Combine.
- `AppDelegate` в классическом стиле (`UIApplicationMain`, ручной
  `UIWindow`).
- Минимальный экран логина (`LoginViewController`) и сетевой клиент
  (`LegacyAPIClient`) на `URLSession` в completion-handler стиле —
  такой API доступен начиная с iOS 7.
- Переиспользуется `KeychainStore`/`APIConfig` из основного таргета: оба
  файла уже написаны на чистом Foundation/Security без API новее iOS 7,
  дублировать их не потребовалось.

## Реалистичный минимум версии: iOS 9.0, не iOS 7

iOS 7-8 исключены из target range сознательно:

- Swift на iOS 7-8 требует либо статической линковки рантайма (раздувает
  бинарник и имеет свои баги в старых компиляторах), либо приложение
  просто не запускается — динамические `libswift*.dylib` появились
  вместе с ABI, стабилизированным только в Swift 5 / iOS 12.2, и Xcode,
  способный собрать Swift 5 под deployment target iOS 7, не существует.
- Практический нижний предел для актуального Swift 5 кода — iOS 9.0
  (последняя версия, где `dataTask(with:completionHandler:)`,
  `URLSession`, Auto Layout API, используемые здесь, точно доступны без
  правок).

## Что НЕ работает и не будет работать без отдельного большого проекта

1. **32-bit (armv7) бинарник.** Актуальный Xcode (используется для
   сборки `ITDOApp`) не умеет линковать armv7 — Apple вырезала эту
   возможность в Xcode 11 (2019). Чтобы получить настоящий 32-bit
   бинарник, `ITDOLegacy` нужно собирать в Xcode 9.x на macOS High
   Sierra/Mojave — отдельный, более старый тулчейн, недоступный в
   среде, где я работаю. Здесь таргет соберётся (на современном Xcode)
   как обычный 64-bit бинарник с deployment target iOS 9.0 — это даёт
   совместимость с iOS 9-12 на 64-bit устройствах (iPhone 5s и новее),
   но не с 32-bit устройствами (iPhone 4s — iPhone 5c).
2. **WebRTC-звонки** (`WebRTCManager.swift` в основном таргете, 39KB) —
   не портированы. Требуют сборки `libwebrtc` под armv7/старый iOS SDK,
   которой в природе почти не существует в поддерживаемом виде — это
   отдельная многонедельная задача (или полный отказ от звонков в
   legacy-клиенте в пользу текстового чата).
3. **Остальные экраны** (лента, чаты, вложения, голосовые сообщения,
   агент/стриминг из `AgentStreamClient.swift`) — не портированы, есть
   только логин. `LegacyAPIClient` — намеренно урезанный скелет, а не
   копия `APIClient.swift`.
4. **Face ID / биометрия** — не подключена в legacy-таргете: `LAContext`
   с `biometryType` появился в iOS 11, а часть API для различения
   Touch ID/Face ID — заметно позже. Если нужен биометрический вход на
   iOS 9-10, это будет только Touch ID через более старый `LAContext`
   API без `biometryType`.

## Следующие шаги (не сделаны, требуют отдельного решения)

- Решить: гнаться за настоящим 32-bit (нужен отдельный CI-раннер со
  старым Xcode/macOS) или ограничиться 64-bit iOS 9-12 (проще,
  реалистичнее, но не покрывает iPhone 4s/5/5c/оригинальный iPad mini).
- Портировать оставшиеся экраны из `ITDOApp/Views` на UIKit по одному.
- Решить судьбу звонков в legacy-клиенте.
